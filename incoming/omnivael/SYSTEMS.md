# Systems: save, main menu, world clock + NPC schedules (branch `systems`)

All three systems are added at runtime by `WorldBootstrap` (any scene with a `GameManager` gets `WorldClock`,
`SaveManager`, `SaveMenuOverlay`, `DayNightCycle`, `NpcScheduleDirector`), so the generated slice scene is unchanged.
Tests: `tools/run-tests.sh` (EditMode + PlayMode, batch). Shots: `SystemsShots.RenderAll` (see below).

## Save system (`Scripts/Systems/Save`)
- Files: `Application.persistentDataPath/saves/{autosave,slot1,slot2,slot3}.json` (+ `.bak` of the previous write;
  atomic temp-file writes; a corrupt file falls back to the backup).
- Schema `SaveGame` v1 (`SaveData.cs`): `player` (scene, zone, position, yaw, HP, reserved name/appearance for the
  character creator), `progression` (`Progression.Snapshot()`), `inventory` (copper + item stacks), `quests`
  (state as text + counters), `world` (day, hours, global flags such as discovered zones), `npcFlags`
  (`NpcRelations`: met / talks / affinity / quest flags), `scenes` (per-scene dead enemies, flags).
  Reserved for later: `properties` (deeds / houses / shops), `party` (co-op members, companions),
  `extensions` (opaque JSON sections from any `ISaveParticipant` registered with `SaveManager.I.Register`).
- Versioning: bump `SaveGame.CurrentVersion`, add a `case` in `SaveMigrations.Migrate` (raw-JSON upgrade). Files
  newer than the game are refused.
- Autosave: on zone change (`GameManager.ZoneChanged`) and every quest step (`QuestManager.StepChanged`: accepted,
  counted kill, objectives done, turned in); coalesced to one write per frame; never while dead or restoring.
- Loading always loads the save's scene, then applies the state on its first frames (`SaveManager.PendingLoad`), so
  more scenes need no extra work: add `ISaveParticipant`s or per-scene state in `scenes`.
- In game: pause (Esc / Start) shows Save Slot 1-3 / Main Menu (mouse, touch, keys 1-3 / M, gamepad D-pad + Y);
  F5 = quicksave to slot 1. `-nosave` disables autosave.

## Main menu (`Scripts/Systems/Menu`, scene `Scenes/MainMenu.unity`, build index 0)
- Generated by `MainMenuBuilder.Build` (menu **Omnivael > Rebuild Main Menu Scene**). `SliceBuilder` now writes
  build settings / player scene lists through `MainMenuBuilder.BuildScenes/ScenePaths` (menu first, then the slice).
- Continue (most recent of autosave + slots), New Game, Load (slot list with summaries), Settings, Quit.
  Text is world-space `TextMesh` in front of the camera (no UI package; renders in camera captures). Placeholder
  look: unlit dusk silhouette of the Hollow, moon, embers, slow camera drift; swap in key art / a UI skin later.
- Input: mouse hover + click, touch tap, keyboard (arrows/WASD, Enter/Space, Esc/Backspace, Left/Right on settings),
  Xbox gamepad through the Input System (D-pad / left stick, A select, B back, D-pad left/right change values).
- Settings (`GameSettings`, PlayerPrefs): Graphics Low / Medium / High / Ultra (matched by name onto the Quality
  levels, which select URP_Mobile / URP_PC; phones default Low, desktop High), master volume, camera mode
  (placeholder only: `GameSettings.CameraMode` / `Changed` for the camera work to read).
- **Character creator hook**: `NewGameFlow.Begin()` loads `NewGameFlow.CharacterCreatorScene` when it is set and in
  the build; the creator then calls `NewGameFlow.EnterWorld(new CharacterChoice { name, appearanceJson })`.
- Automated player runs with `-omnishots` (AutoShots tour) skip the menu straight into the slice (`-omnimenu` keeps it).

## World clock, day/night, NPC schedules (`Scripts/Systems/World`)
- `WorldClock`: `dayLengthMinutes` (default 24 real minutes = 1 day), new games start 09:00 (the slice's original
  daylight), pauses with the game, saved/restored.
- `DayNightCycle`: sun path (09:00 = the original `Euler(52,-35)`), dim blue moon at night, colour / intensity /
  trilight ambient / fog / camera background keyed by hour, hero lantern at night; leaves the Well-Warrens alone.
  **Pluggable**: implement `ITimeOfDayReceiver` (gets hours + daylight every frame; `OwnsLighting = true` makes the
  cycle stop driving lights), or any component named `LightingRig` is detected and gets `SendMessage("SetTimeOfDay", hours)`.
- Schedules are data: `Resources/Schedules/<SceneName>.json`. Waypoints (homes, doors, posts, tavern yard, market,
  well, woodpile, shrine, garden...) can follow a scene object (`fromObject` + `offset`) or an NPC's authored spot
  (`fromNpc`) and fall back to `pos`, so the data survives layout changes. Blocks: `from`/`to` hours (may wrap
  midnight), `activity` (Sleep / Work / Eat / Tavern / Market / Wander), `place`. `villagers` spawn ambient NPCs.
- `NpcScheduleDirector` builds a runtime NavMesh over the town (or uses a baked one), spawns villagers, attaches
  `ScheduleComponent`s. NPCs walk with `NavMeshAgent` (animation via the existing `CharacterAnimDriver`), wander /
  dwell at places, walk to the door and are hidden for indoor places (door "fade" = hide for now), come back out of
  the same door, hold still while you talk to them or block their way, and use trigger colliders while walking.
- Ambient villagers (Tomas the Woodcutter, Hanne the Weaver, Old Bram, Wenna the Farmhand) are clones of the Elmin /
  Mirella models until they get their own art: set `prefab` (Resources path) in the JSON.

## Screenshots (edit mode, needs xvfb, no -nographics)
```
xvfb-run -a -s "-screen 0 1280x720x24 +extension GLX" Unity -batchmode -quit -projectPath . -force-glcore \
  -executeMethod Omnivael.EditorTools.SystemsShots.RenderAll -shotdir /path/to/dir
```
Writes `mainmenu.png`, `mainmenu_settings.png`, `town_0730_morning.png`, `town_1230_midday.png` (+ `_tavern_yard`),
`town_1900_dusk.png`, `town_2330_night.png` (NPCs snapped to their schedule, idle pose sampled).
